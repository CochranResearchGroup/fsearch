## What to build

An operator can assess comparative evidence, admit actual storage, and adopt the packaged backend with reversible installed configuration and direct CLI/MCP verification.

## Acceptance criteria

- [ ] Freeze workload and latency/memory/resource gates before measuring; report cold vs warm runs and compare appropriately scoped candidates.
- [ ] Assess physical backing-storage and mount admission separately from benchmark success; synthetic evidence is not real-root authorization.
- [ ] Qualify packaged CLI/MCP output, cancellation, updates, monitors, process/FD cleanup and failure recovery.
- [ ] Prepare rollback before activation; verify installed source identity, user configuration preservation and actual direct runtime calls.
- [ ] Execute real-root indexing and installation only when the operator directs that phase; preserve prior accepted evidence.
